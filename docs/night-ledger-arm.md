`agent_board.night.ledger_arm.compare_and_set_arm` publishes one existing-ledger metadata row with an explicit prior tuple or explicit absence. It leaves every legacy Ledger method, guard, gate, exec path and other production caller unchanged. No timer, manager, journal mutation, network operation, enqueue or emission-lock acquisition occurs. It never creates, migrates, resets, repairs, adopts or provisions a store. These boundaries require trusted caller-supplied ordering and lifecycle exclusion from preflight through confirmed close; schema/file/sidecar replacement, restore and uncooperating writers are excluded externally. There is no atomic VFS-open proof.

Input validation precedes private-file/sidecar/header checks. Schema validation, identity validation/matching and target-arm validation/comparison occur inside a fresh BEGIN IMMEDIATE. Version3/delete mode and all16 catalog objects are checked before row work. Identity/catalog enumerations are explicitly capped, and the target uses the arm primary index. Context and tuples remain correlation metadata, not authenticated authority.

A pre-open sidecar yields SIDECAR_PRESENT without diagnosing whether it is live or debris. A typed SQLite busy/locked error before successful BEGIN yields BUSY and NOT_ATTEMPTED. Busy at COMMIT remains SQLITE_FAILURE and UNKNOWN. The single terminal fault uses cleanup-first precedence, independently from mutation/resource knowledge.

Changed success commits one insert/conditional replacement and reports COMMITTED. Validated unchanged success explicitly rolls back, reports ROLLED_BACK/changed=false and never attempts COMMIT. Only normal completion plus confirmed closure and no fault/refusal returns StoredArm. Failed intentional rollback is never repeated, and close-established rollback does not manufacture a successful no-op. Every COMMIT exception remains UNKNOWN; known commit survives close failure.

Fresh exact-head independent source review is requested for this standalone primitive only. Source acceptance and merge remain outstanding. Full combined gates and current-base agreement must be refreshed after any changes; passing owner tests is not a substitute for review.

The API is write-only, with no sanctioned recovery observer after UNKNOWN or a lost reply. A conflict/no-op cannot confirm the past write. A separate reconciliation protocol is required and cannot rewrite original uncertainty.

SIDECAR_PRESENT does not seal the file against other SQLite openers. After a confirmed writer crash, its interrupted transaction cannot continue committing by itself. If the retained journal is hot, a subsequent capable read-write SQLite opener with the required locks can automatically roll back uncommitted work during ordinary access. The existing legacy Ledger connection path (timeout5) can be such an opener, without producing a CAS recovery receipt. That side effect can remove the sidecar and make this primitive writable again; it is not this primitive repairing the store or a new reconciliation protocol. A SIDECAR_PRESENT streak alone does not identify a hot journal, prove writer death or diagnose damage. A transaction that committed before a lost reply may already be durable. Neither journal recovery nor later sidecar absence rewrites an original COMMIT-exception UNKNOWN, authenticates an operation outcome, authorizes a retry/adoption or permits slot settlement/refunds.

Legacy unconditional writers can overwrite before or after this transaction; value-CAS supplies no ABA/epoch/non-reuse protection. Invalid legacy rows remain unwritable here. Private path checks do not pin SQLite's actual descriptor or protect against hostile same-UID/root actors. Lifecycle exclusion, resource/corruption VM bounds, all-writer ordering and native timer-before-publication truth require separate evidence before integration. Neither matching identity nor StoredArm supplies eligibility, native containment, settlement or production provenance.
